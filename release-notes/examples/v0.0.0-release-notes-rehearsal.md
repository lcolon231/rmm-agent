## Upgrade

### Prerequisites

- Verify an encrypted backup and retain its immutable manifest before changing the database or server.
- Confirm the server, dashboard, agent, Alembic revision, and command-envelope versions match this record.

### Steps

1. Pause command dispatch and external agent rollout automation.
2. Apply Alembic revision 0010, then deploy the server and dashboard from the recorded source commit.
3. Deploy the checksum-verified agent and installer to owned canary endpoints before expanding.

### Verification

- Confirm the server revision guard passes and a known operator can authenticate.
- Confirm canary agents advertise command-v3 and complete one benign command exactly once.
- Verify the audit chain, external anchor publication, backup evidence, and release artifact attestations.

## Rollback

### Decision path

1. Prefer a forward fix when the current schema can remain in place.
2. Redeploy the last-known-good components only when their required schema exactly matches the live database.
3. Otherwise preserve the failed state, approve the data-loss window, and restore the exact-revision verified backup.
